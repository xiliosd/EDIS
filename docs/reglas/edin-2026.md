# Reglas de EDIN 2026

Reglas de saltos del cuestionario EDIN 2026, tal como las carga el motor compartido (backend y
frontend). La semilla está en `backend/src/main/resources/rules-seed/EDIN-2026.json` (versión 2).
Viene del JavaScript heredado `General/JavaScript/FrmValida.js` y de la tabla `FRM_SALTO`. Todos los
datos de este documento son metadatos del cuestionario; no hay respuestas ni datos de personas.

Decisión asociada: D20 del [spec](../superpowers/specs/2026-10-14-formulario-web-design.md): cada regla
especial se migra por su **intención** (comentario del JS más el ítem que `FRM_SALTO` marca como
disparador), no por sus índices.

## Reglas especiales

Las posiciones del JS son índices base 0 entre los ítems (`TIPO = 'L'`) de la página, como `PP[]` en el
PHP. En `FRM_SALTO` se marcan con `VALOR_SALTO = 1`. En dos de ellas los índices escritos a mano no
coinciden con el orden de 2026 (se quedaron del cuestionario de 2024); la columna "JS literal" muestra
qué haría el índice tal como está escrito.

(1) Usa el id `legacy-C09G` porque reemplaza al salto genérico de `C09G` (ver abajo).

## Saltos genéricos

Un salto genérico (`VALOR_SALTO = 2`) dice: si el combo vale `2`, se deshabilitan los `SALTO` combos
siguientes. No va en la semilla; el backend lo traduce desde la base de datos. En 2026 son siete:

| Disparador | Deshabilita |
| :-- | :-- |
| `B10` = `2` | `B11` |
| `C09G` = `2` | `C10` (se reemplaza; ver abajo) |
| `C19` = `2` | `C20A`, `C20B` |
| `D04` = `2` | `D05`, `D06A`–`D06E`, `D07` |
| `E05` = `2` | `E06A`–`E06D` |
| `E07` = `2` | `E08A`–`E08D` |
| `G02` = `2` | `G03A`–`G03E` |

**Reemplazo `legacy-C09G`.** El genérico de `C09G` deshabilita `C10` apenas `C09G` es "No", aunque las
otras C09 sean "Sí", lo que contradice la regla del JS ("todas = No"). La semilla define una regla
con el mismo id `legacy-C09G` (todas las C09A–C09G = `2` deshabilitan `C10`). En `EffectiveRulesService`, una regla del
archivo con id `legacy-<COL>` reemplaza al salto genérico de esa columna.

## Notas para el dueño del producto

1. **F04I con `f04-todas-no` y `f04-alguna-si`.** Combinadas, `F04I` ("ninguna") queda habilitada solo
   si ninguna de `F04A`–`F04H` vale `1` o `9` y no todas valen `2`. Es decir, queda habilitada con
   respuestas vacías o mezcladas de `2` y vacías, nunca con todas en "No".
2. **Conteos de `SALTO` en `FRM_SALTO`.** Para las filas de reglas especiales, el conteo `SALTO` no
   coincide con los destinos del JS: `C13` = 6 (JS: 8), `C07A` = 5 (JS: 8), `F03A` = 10 (JS: 9),
   `F03J` = 5 (JS: 4), `G05` = 5 (JS: 1). La semilla sigue la intención del JS; Oscar lo confirmó el
   2026-10-16.

## Origen de `db/reference/frm-2026-orden.csv`

El archivo contiene solo metadatos del cuestionario. Se generó a partir de las tablas `FRM_*` de una
copia de seguridad de la base suministrada por Oscar; no se tomó ninguna tabla de respuestas, muestra
ni usuarios. Se emuló la consulta de `QuestionnaireRepository` para `PROY LIKE 'EDIN%'` y
`ANIO = '2026'`, con los ítems `TIPO = 'L'` en orden `GRUPO, ORDEN`. Coincide ítem por ítem con las
listas de `Tabla()` en `Funciones.php`. Las columnas son `PAGINA`, `POSICION`, `NUMERAL`, `COLUMNA`,
`COD_OBJ`, `GRUPO_RESPUESTA`, `SALTO` y `VALOR_SALTO`.
